ระบบสะสมแต้มจากการลงห้องเสียง (Voice Activity Points) และการจำกัดการรับแต้มต่อวันตามเลเวล/ยศ มีการเก็บและประมวลผลข้อมูลใน 3 ส่วนหลักดังนี้ค่ะ:

---

### 1. ฐานข้อมูลหลัก (Supabase Database)
ข้อมูลแต้มและการจำกัดประจำวันของผู้ใช้แต่ละคนจะถูกบันทึกไว้ใน **Supabase Database** ตาราง **`user_points`** ซึ่งมีคอลัมน์สำคัญดังนี้:
* **`discord_id`**: ID ของผู้ใช้ Discord
* **`points`**: แต้มสะสมปัจจุบันของผู้ใช้
* **`max_cap`**: ขีดจำกัดแต้มสะสมสูงสุดตามยศ/เลเวล
* **`daily_points`**: แต้มสะสมที่ได้รับไปแล้วภายในวันนั้น
* **`last_reset_date`**: วันที่ล่าสุดที่มีการบันทึกแต้มประจำวัน (ใช้เปรียบเทียบกับวันที่ปัจจุบันในโซนเวลา `Asia/Bangkok` เพื่อรีเซ็ต `daily_points` เมื่อขึ้นวันใหม่)

---

### 2. การตั้งค่าเพดานแต้มตามเลเวล/ยศ (Configuration File)
การกำหนดว่ายศ/เลเวลไหนได้เพดานสะสมสูงสุดเท่าไร เก็บไว้ในไฟล์คอนฟิก:
* 📄 [src/points/settingCheckIn.json](file:///d:/bearcafe-bot/src/points/settingCheckIn.json#L61-L75)
  * **`ROLE_CAPS`**: จับคู่ Discord Role ID กับค่า `max_cap` (เช่น เลเวลยศต่างๆ = 1,000, 1,500, 2,000 ... สูงสุด 12,000 แต้ม)
  * **`DEFAULT_CAP`**: ค่าเริ่มต้นกรณีไม่มี Role พิเศษ (750 แต้ม)

---

### 3. ตารางและเงื่อนไขการคำนวณ Daily Cap (Supabase Edge Function)
ระบบแจกแต้มห้องเสียงควบคุมด้วย Supabase Edge Function ในไฟล์:
* 📄 [functions/voice-activity-points/index.ts](file:///d:/bearcafe-bot/functions/voice-activity-points/index.ts#L22-L31)

### 🔄 สรุปขั้นตอนการทำงาน
1. บอทจับระยะเวลาการอยู่ในห้องเสียงผ่าน [src/features/voicePoints.js](file:///d:/bearcafe-bot/src/features/voicePoints.js#L157-L194) และส่งข้อมูลไปยัง API
2. Edge Function อ่านค่า `daily_points` และ `last_reset_date` จากตาราง `user_points`
3. หากเป็นวันใหม่ (ตามเวลาประเทศไทย) ระบบจะรีเซ็ตนับ `daily_points` เริ่มต้นที่ `0`
4. หาก `daily_points` ถึงขีดจำกัด `dailyCap` ของยศนั้นๆ แล้ว ระบบจะหยุดแจกแต้มเพิ่มสำหรับวันนั้นทันทีค่ะ
